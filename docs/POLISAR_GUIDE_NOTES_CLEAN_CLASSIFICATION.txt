# Pol-ISARSpaceTarget-1.0 Clean Classification Notebook Notes

Notebook reviewed: `POLISAR_ComplexCNN_Classification_CLEAN.ipynb`

## 1. Current Objective

The current notebook is a clean classification-only baseline for the Pol-ISARSpaceTarget-1.0 dataset. It avoids the earlier unnecessary detection/objectness components and focuses only on target class recognition.

Target classes:

- Capella
- HISEA1
- QPSSAR
- Radarsat2
- StarLink
- Worldview4

## 2. Dataset Reading

The notebook reads the original `.dat` files using the same layout as the dataset author's `Tools/DataReadPython.py`.

Each sample is reconstructed from four polarimetric complex channels:

- `HH`
- `HV`
- `VH`
- `VV`

Each `.dat` file stores interleaved float32 real and imaginary values:

- even indices: real part
- odd indices: imaginary part

Each channel is reshaped to `256 x 256`. The four channels are arranged as a full-polarimetric matrix:

[HH HV
 VH VV]

The model input is then stacked as:

[HH, HV, VH, VV]

Final input tensor shape:

[4, 256, 256], complex64

## 3. Preprocessing / Normalization Used

No augmentation is applied to validation or test data. Training augmentation is optional and controlled separately.

The notebook uses the original image size, `256 x 256`, by default.

The earlier per-sample max-amplitude normalization has been removed because it allowed each validation/test sample to determine its own scaling.

The corrected notebook now follows this rule:

- compute real/imag mean and standard deviation from training data only
- apply the same training mean/std to train, validation, and test
- validation/test statistics are never used for normalization
- set `use_train_standardization = False` to run a fully raw no-normalization experiment

For the complex tensor, real and imaginary parts are standardized separately:

real = (real - train_real_mean) / train_real_std
imag = (imag - train_imag_mean) / train_imag_std

Magnitude and phase features are then extracted from this standardized complex input. The previous per-sample magnitude max normalization has also been removed.

## 4. Model Architecture

The notebook uses a simple Complex CNN classifier.

Main components:

- Complex convolution layer
- Complex batch normalization
- Complex ModReLU activation
- Complex residual blocks
- Fully connected complex feature layer
- Magnitude-phase feature branch
- Final classification layer

Complex convolution follows:

(a + jb)(c + jd) = (ac - bd) + j(ad + bc)

The Complex CNN feature vector is tapped from:

fc_complex

Magnitude and phase are also extracted, normalized, and passed through a small feature branch.

Final fused feature:

fused_features = concat(complex_fc_features, mag_phase_features)

The fused feature is passed to a softmax classifier.

## 5A. Corrected Experimental Protocol Added After Guide Feedback

The guide correctly pointed out that accuracy of `1.0` does not mean the model is perfect. It may indicate issues with data split, leakage, or an overly easy learning problem.

The guide also pointed out that normalization must not be computed using validation/test samples. This has been corrected.

The notebook has therefore been reordered into a cleaner research protocol:

1. Dataset reading and audit
2. Compute normalization statistics from training data only
3. Apply the same train statistics to train, validation, and test
4. Magnitude/phase feature extraction
5. Complex CNN definition
6. Learning-rate sweep
7. Augmentation check
8. Stratified K-fold validation
9. Select final settings
10. Final train on train + valid
11. Final test once on untouched test split

This means the final model is not trained first and justified later. The verification steps come before the final training/test claim.

The three verification steps are:

1. Learning-rate tuning

The notebook now includes a learning-rate sweep section with:

1e-4, 3e-4, 1e-3

This checks whether the result is stable across learning rates or depends on one lucky training configuration.

2. Data augmentation

Training augmentation has been added only to the training split. Validation and test data are kept unchanged.

Augmentations used:

- horizontal flip
- vertical flip
- 90-degree rotations
- small complex Gaussian noise

The augmentation is applied consistently to real and imaginary parts so the complex structure is preserved.

3. Stratified K-fold validation

The notebook now includes a stratified K-fold section.

Important protocol:

- K-fold is run on `train + valid`.
- The official `test` split is not used inside K-fold.
- The official `test` split remains a final holdout.

This gives a better estimate of whether the model is stable across different train/validation partitions.

The LR sweep and K-fold cells are controlled by:

RUN_LR_SWEEP = False
RUN_KFOLD_STUDY = False

They can be changed to `True` in Colab when running the verification experiments.

After these checks, the notebook selects final settings. If LR sweep results exist, the best LR by validation macro-F1 is selected. If they are not run, the conservative default `3e-4` is used.

The final model is then trained on:

train + valid

The official `test` split is evaluated only after final settings are fixed.

## 8. Important Comments / Suspicious Points

The result should not be overclaimed.

The 100% test accuracy and full diagonal confusion matrix are suspicious for a sparse simulated ISAR dataset. It may be correct for the official split, but it needs stronger validation.

Observed concerns:

- Validation accuracy changes significantly across epochs.
- Best checkpoint gives perfect test performance.
- Test set is small: only 162 samples, 27 per class.
- The split is balanced but may still be easy because target identity and simulated scattering structure may be highly class-specific.
- Magnitude structure alone may carry strong target information.
- If magnitude-only also gives 100%, phase fusion and feature selection are not needed for improving this official split; they are useful only for robustness analysis or harder splits.
- Exact file-hash overlap has not yet been completed.

Therefore, the current result should be written as:

The official split appears highly separable under the clean Complex CNN baseline.
Further leakage checks and harder split protocols are required before claiming robust generalization.

After the latest update, the next result table should include:

- LR sweep result
- augmentation setting used
- K-fold mean and standard deviation
- final untouched-test result
